# Security and privacy policy for this public repository

## Public-by-design, not everything-public

This repository publishes **sanitized facts and architecture**.

The private build history contains deeper evidence that is not automatically safe to publish.

## Never publish here

- passwords;
- API keys;
- tokens;
- cookies;
- secret keys;
- private recipient addresses;
- prospect/customer private data;
- banking identifiers;
- payment credentials;
- private correspondence;
- raw model transcripts containing sensitive content;
- internal paths that materially increase exploitability;
- source code that the owner has not explicitly released.

## Evidence transformation

A private artifact can support a public fact without the artifact itself becoming public.

Example:

**Public fact**

> A scheduled CEO cycle completed after passing ten operating preconditions and persisted a verified executive result.

**Private evidence may still remain private**

- local filesystem paths;
- raw logs;
- credentials;
- customer identities;
- full transcripts;
- security-sensitive configuration.

## Claim language

Publication should preserve evidence level.

Examples:

- PROVIDER ACCEPTED
- SENT-FOLDER VERIFIED
- RECIPIENT DELIVERY UNKNOWN
- HUMAN REPLY NOT PROVEN
- CASH COLLECTION NOT PROVEN

## Corrections

If a public claim is later found wrong:

1. preserve the historical claim where appropriate;
2. add a correction;
3. explain the evidence that changed the conclusion;
4. update the current-state page;
5. do not silently erase the learning history.

## Security reporting

Do not post credentials, exploit details or private customer information in a public issue.

For a potentially sensitive security issue, request a private contact channel without reproducing the sensitive material publicly.
